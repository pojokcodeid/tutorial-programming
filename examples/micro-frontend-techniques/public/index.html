Tiga demo, satu server

01 · iframe

Dokumen di dalam dokumen

Remote hidup di dokumen terpisah. CSS, JavaScript, dan global scope-nya tidak bercampur dengan shell.

  • Isolasi paling total
  • Komunikasi lewat postMessage
  • Tinggi dan layout harus diatur shell

Bandingkan

Trade-off yang perlu kamu pilih

Tidak ada pemenang mutlak. Pilihan bergantung pada tingkat isolasi, tim, dan seberapa sering remote berubah.

Aspek iframe Web Component Import map
Isolasi gaya Total — dokumen punya CSS sendiri. Kuat — Shadow DOM mengunci gaya internal. Tidak ada — semua CSS berbagi satu dokumen.
Isolasi JavaScript Total — global scope dan error terpisah. Sebagian — DOM terisolasi, global tetap bersama. Tidak ada — modul berbagi global dan runtime.
Komunikasi postMessage, asinkron, data diserialisasi. CustomEvent, mengalir di DOM. Panggilan fungsi / import langsung.
Integrasi layout Kotak tetap; tinggi dan scroll diatur shell. Mengalir seperti elemen biasa. Mengalir seperti elemen biasa.
SEO & aksesibilitas Paling sulit; konten di dokumen terpisah. Baik; DOM dan fokus tetap di halaman. Baik; DOM dan fokus tetap di halaman.
Biaya integrasi Rendah untuk mulai, tinggi untuk komunikasi. Sedang; butuh kontrak atribut/event yang jelas. Rendah jika semua pihak memakai ESM.
Paling cocok untuk Aplikasi legacy, vendor, atau remote yang benar-benar asing. Widget lintas framework yang perlu tampil menyatu. Berbagi modul dan lazy load dalam satu stack.

Urutan yang disarankan

Mulai dari iframe untuk merasakan isolasi paling ketat. Lanjut ke Web Component untuk melihat isolasi gaya yang lebih nyaman. Terakhir, import map untuk merasakan integrasi paling langsung — sekaligus risikonya.

Alur latihan

Cara memakai lab ini

Sekitar 15 menit jika kamu mengikuti urutannya.

  1. Buka demo iframe Kirim pesan dari shell, balas dari remote, lalu tekan tombol yang mencoba mengakses DOM shell. Perhatikan error yang muncul.
  2. Buka demo Web Component Tambahkan produk ke keranjang, lalu nyalakan “serangan gaya”. Bandingkan kartu biasa dengan kartu Shadow DOM.
  3. Buka demo import map Muat remote, lalu coba modul rusak. Pastikan shell tetap hidup dan pesan error tampil dengan jelas.
  4. Bandingkan dan catat Buka DevTools → Network dan Elements. Lihat berapa request, di mana CSS berada, dan bagaimana event bergerak.

Catatan tentang satu origin. Semua demo dilayani dari http://localhost:4180 supaya mudah dijalankan. Di produksi, remote sering berada di origin berbeda. Saat itu terjadi, kamu perlu memikirkan CORS, CSP, autentikasi, targetOrigin yang spesifik, dan versioning modul.
