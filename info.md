Materi proyek praktis membangun satu aplikasi React lengkap (Dashboard Toko):

  - https://axios-http.com/docs/intro
  - https://github.com/typicode/json-server

1. Fondasi Proyek
   - Pengenalan & Setup Proyek: gambaran fitur, perpustakaan yang dipakai (React + Vite, Ant Design, React Router DOM, Axios, json-server, JWT), struktur folder, dan menjalankan frontend + backend berdampingan.
   - json-server sebagai Dummy Backend: db.json (users, products, refreshTokens), json-server programatik lewat server.js, endpoint auth (register, login, refresh, logout, me), middleware authenticate & requireRole, serta aturan akses resource.
2. Komponen & Navigasi
   - Custom Component dengan Ant Design: komponen presentasional (PageHeader, StatCard), membungkus Table Ant Design menjadi ProductTable, layout AppShell dengan menu berbasis peran.
   - Routing dengan React Router DOM: peta rute App.jsx, nested route + Outlet, layout route, ProtectedRoute dengan Navigate state, rute dinamis useParams, useNavigate & useLocation, halaman 404.
3. State & HTTP
   - Context API: masalah prop drilling, AuthContext + custom hook useAuth, pemulihan sesi, jembatan event "sesi berakhir" dari axios.
   - Axios: instance dengan baseURL, interceptor request (header Authorization), modul API terpisah (authApi, productApi, userApi), pola loading & error di halaman.
4. Keamanan
   - Authentication & Authorization: form login/register dengan validasi Ant Design, penyimpanan token, ProtectedRoute & RoleGate, otorisasi di sisi tampilan beserta batasannya.
   - Access & Refresh Token Otomatis: alur 401 → refresh → retry, antrean refresh untuk banyak request, rotasi & pencabutan token di server, pengamatan lewat DevTools dan curl.

## Topik Lucee CFML

  - https://rorylaitila.gitbooks.io/lucee/content/

     - Apa itu CFML (ColdFusion Markup Language) dan keunggulan Lucee (Open Source & High Performance).
     - Instalasi Lucee Server lokal menggunakan CommandBox (box server start).
     - Pemahaman arsitektur dasar Lucee yang berjalan di atas JVM (Java Virtual Machine).
     - Setup Code Editor (Neovim / VS Code) dengan extension CFML / CFLint.
   - Sintaks Dasar CFML (Tag-based vs CFScript)
     - Perbedaan sintaks Tag-based (<cfset>, <cfif>) dan CFScript (sintaks mirip JavaScript/Java).
     - Variabel dan Tipe Data: String, Number, Boolean, Date.
     - Variabel Scopes dasar: variables, arguments, local, session, application, request.
     - Struktur Kontrol: Conditional (if/else, switch/case) dan Looping (for, while, cfloop).
   - Data Structures & Manipulasi Data
     - Arrays: Deklarasi, manipulasi, serta fungsi bawaan (arrayAppend, arrayLen, arrayMap, arrayFilter).
     - Structures (Struct): Key-value pair, manipulasi struct, dan nested struct.
     - Queries: Konsep data query bawaan CFML.

2. Pengolahan Data & Pemrograman Menengah (Intermediate)
   - Interaksi Database (SQL & ORM)
     - Koneksi Database via Lucee Admin atau file konfigurasi Application.cfc (Datasource setup).
     - Mengabaikan Vulnerability: Menggunakan <cfquery> dengan <cfqueryparam> (Pencegahan SQL Injection).
     - Operasi CRUD (Create, Read, Update, Delete).
     - Dasar-dasar Lucee ORM (Hibernate integration) untuk pemetaan objek database.

   - Modularisasi & Reusability
     - User Defined Functions (UDF): Deklarasi fungsi, argumen, return type, dan scope lokal (local).
     - ColdFusion Components (CFC): Konsep dasar class/component, properti, method (cffunction), dan akses modifier (public, private, package).
     - Penggunaan cfinclude dan cfmodule secara efisien.

   - Konfigurasinya & Lifecycle Aplikasi (Application.cfc)
     - Memahami struktur dan lifecycle event di Application.cfc:
     - onApplicationStart()
     - onRequestStart() / onRequestEnd()
     - onSessionStart() / onSessionEnd()
     - onError()
     - Pengelolaan Session Management dan Cookies.

3. Arsitektur Modern & Lanjutan (Advanced)
   - Object-Oriented Programming (OOP) di CFML
     - Konsep Encapsulation, Inheritance, Polymorphism, dan Interfaces di CFC.
     - Dependency Injection & Inversion of Control (IoC) menggunakan framework seperti WireBox.
     - Design Patterns dasar dalam CFML (DAO, Gateway, Factory, Singleton).

   - Pengembangan RESTful API & Web Services
     - Membuat REST API native di Lucee menggunakan annotation pada CFC (restpath, httpmethod).
     - Penanganan request/response JSON & XML (serializeJson, deserializeJson).
     - Otentikasi dan Otorisasi API (JWT / Token-based Authentication).

4. Performa, Deployment, & Profesional (Expert / Senior)
   - Lucee Administration & Configuration Management
     - Pengelolaan Lucee Web Admin dan Server Admin.
     - Konfigurasi berbasis kode/environment (lucee-web.xml.cfm, Application.cfc settings, environment variables).
     - Pengaturan Cache Engine (Redis, Ehcache, Memcached) untuk optimasi query dan page caching.

   - Integrasi Java & Sistem Eksternal
     - Interoperabilitas Java: Memanggil class Java eksternal atau JAR library langsung dari CFML (CreateObject("java", ...) / JavaCast).
     - Penanganan operasi asinkron: cfthread, Task Scheduling, dan Event Gateways.
     - File Management & Document Processing (PDF Generation via cfdocument, Spreadsheet via Apache POI / cfspreadsheet).

   - Testing & Code Quality
     - Unit Testing dan Integration Testing menggunakan TestBox.
     - Static Code Analysis & Linting menggunakan CFLint.
     - Logging dan Error Monitoring/Tracking (Sentry, LogBox, custom exception handling).

   - DevOps, Deployment, & Security - Deployment menggunakan Docker container & CommandBox Docker Images.
     - Web Server Integration: Mengintegrasikan Lucee dengan Nginx atau IIS via BonCode / AJP Connector.
     - Hardening Security Lucee: Mencegah XSS, CSRF, File Upload Vulnerability, dan Lockdown Lucee Admin.
     - Profiling & Performance Tuning: Identifikasi memory leak, JVM tuning, dan optimasi garbage collection.

## Topik Mengenai RabbitMQ (Message Broker)

Materi RabbitMQ (message broker & protokol AMQP). Kebutuhan lengkap ada di `rabbitmq.md` (RabbitMQ
Mastery Roadmap); materi disusun 20 pelajaran berbahasa Indonesia dengan diagram,
contoh kode, dan kuis, seluruhnya bisa dipraktikkan mandiri dan **gratis**
(Podman rootless, image `rabbitmq:3-management`, tanpa layanan berbayar).

- Rujukan
  - https://www.rabbitmq.com/docs
  - https://www.rabbitmq.com/tutorials
  - https://www.rabbitmq.com/docs/management
  - https://www.rabbitmq.com/docs/clustering

- Materi yang harus ada

1. Pengenalan (Phase 0–1)
   - Konsep message broker, komunikasi sinkron vs asinkron, peran broker (antre, routing, menyerahkan ketika siap), decoupling.
   - Setup RabbitMQ dengan Podman (`rabbitmq:3-management`), port 5672 (AMQP) & 15672 (dashboard), kredensial `admin`/`admin123`.
2. Arsitektur & Exchange (Phase 2–3)
   - Alur pesan RabbitMQ: producer → exchange → binding → queue → consumer.
   - Tipe exchange: default (nama antrean), direct, fanout, topic (wildcard `*`/`#`), headers (x-match all/any).
3. Keandalan Pesan (Phase 4)
   - Durability antrean (`durable`) vs persistence pesan (`persistent`), pengaruhnya saat restart broker.
   - Consumer acknowledgment (ACK/NACK), requeue vs DLX, prefetch (QoS) & fair dispatch.
   - Dead Letter Exchange (DLX) & DLQ: nack requeue=false, TTL, x-max-length; pola retry berbasis TTL.
   - TTL pesan (expiration) & antrean (x-message-ttl), priority queue (x-max-priority 0–255).
4. Integrasi Aplikasi (Phase 5)
   - Node.js (amqplib): publisher, worker, prefetch, graceful shutdown.
   - Go (amqp091-go): QueueDeclare, PublishWithContext, Qos, goroutine, signal handling.
   - Java (Spring AMQP): RabbitTemplate, @RabbitListener, konversi JSON, retry & DLQ deklaratif.
5. High Availability & Multi-Region (Phase 6)
   - Cluster RabbitMQ (Erlang cookie, join_cluster), quorum queue (Raft) vs mirrored queue (legacy).
   - Federation (upstream-downstream, exchange-to-exchange) & shovel (queue-to-remote, ack-mode on-confirm).
6. Keamanan & Monitoring (Phase 7)
   - User, vhost, permission (configure/write/read) dengan pola regex; TLS (port 5671, amqps).
   - Monitoring: plugin `rabbitmq_prometheus`, endpoint `/metrics`, Prometheus + Grafana, metrik kunci & alarm.
7. Production Readiness & Praktik Proyek
   - Tuning: publisher confirm, watermark memori, disk limit, heartbeat; anti-pattern yang harus dihindari.
   - Proyek 1: worker queue sederhana (publisher, antrean durable, worker dengan ACK & prefetch).
   - Proyek 2: publisher-subscriber (fanout) dengan retry & dead letter queue.
   - Proyek 3: graceful shutdown — cancel consumer, selesaikan yang berjalan, tutup channel & koneksi.

## Topik Contoh Fullstack Project Microservices

Materi **Contoh Fullstack Project Microservices** — satu proyek nyata bernama **TokoKita** (toko daring) dibangun end-to-end lalu diuraikan menjadi 12 pelajaran berbahasa Indonesia lengkap dengan figur diagram, contoh kode, dan kuis 40 soal. Kode proyek contoh tersedia di `examples/fullstack-microservice/` dan teruji berjalan (tujuh container sehat dalam satu perintah `podman-compose up -d --build`).

- Rujukan
  - https://martinfowler.com/articles/microservices.html
  - https://12factor.net/
  - https://podman.io/docs
  - https://mariadb.com/kb/en/documentation/
  - https://go.dev/doc/
  - https://redis.io/docs/latest/
  - https://www.rabbitmq.com/docs
  - https://react.dev/
  - https://ant.design/docs/react/introduce
  - https://vite.dev/guide/

- Materi yang harus ada

1. Pengenalan Arsitektur
   - Mengapa microservices, batas service & database-per-service, keputusan komunikasi sinkron (HTTP) vs asinkron (pesan), peta arsitektur TokoKita (browser → nginx → tiga service → MariaDB/Redis/RabbitMQ).
   - Kontrak antar service, snapshot data pesanan, degradasi terkendali, dan batas-batas yang sengaja dibuat ketat lewat izin database.
2. Setup Podman (Container)
   - Podman rootless vs Docker, podman machine di macOS, bind mount & virtualisasi volume, image, container, jaringan, dan siklus perintah sehari-hari (run/ps/logs/exec/rm).
   - Tiga prinsip container di proyek nyata: proses sebagai non-root, healthcheck, dan konfigurasi lewat environment (12-factor).
3. MariaDB Multi-Database
   - Satu instance tiga database (product_db, order_db, notification_db), satu pengguna per service dengan GRANT sempit, skema idempoten dari folder migrations, ukuran kolom (VARCHAR vs TEXT), index, TIMESTAMP, dan pemeriksaan setelah boot.
4. Backend Go — Fondasi Service
   - Pola main.go (konfigurasi env → waitForDB → wiring → server → shutdown), net/http Go 1.22+ (method + path), context & timeout berlapis, kode status HTTP, penanganan galat terstruktur (problem+JSON), dan struktur lapisan handler/store.
5. Product Service — REST API CRUD
   - Model produk sebagai kontrak JSON, repository dengan parameterized query, endpoint CRUD lengkap, kode status 200/201/204/400/404/422/500, validasi input, serta uji curl pertama.
6. Redis Cache di Depan Database
   - Pola cache-aside (baca HIT/MISS, invalidasi setelah tulis), TTL 30 detik, header X-Cache, degradasi saat Redis mati, dan pengukuran hit rate.
7. Order Service — Bisnis & Idempotensi
   - Validasi produk ke katalog (HTTP timeout), total dihitung di server, snapshot pesanan, kunci idempotensi (header + UNIQUE), dan konsekuensi kegagalan antar-service.
8. RabbitMQ — Sisi Penerbit
   - Topologi (exchange topic tokokita.events, routing key order.* , binding, queue durable), pesan persistent, timeout publish, dan keputusan melanjutkan pesanan vs membatalkan saat broker bermasalah.
9. RabbitMQ — Sisi Konsumer (Notification Service)
   - Deklarasi topologi dari konsumen, autoAck=false & ACK/NACK manual, prefetch (QoS), deduplikasi event_id, reconnect loop tanpa batas, dan API notifikasi (list + tandai baca + hitungan unread).
10. Frontend React & Ant Design
   - Kerangka aplikasi (main.jsx → App.jsx → AppShell → halaman), pola halaman konsisten (state, muat, cleanup), lapisan API axios (baseURL /api), komponen Ant Design (Table, Form, Modal, Badge), dan fan-in Promise.all di dashboard.
11. Integrasi Frontend ↔ Backend
   - nginx location tanpa garis miring + proxy_pass ber-URI, proxy Vite mode dev yang identik, satu origin tanpa CORS, polling lonceng tiap 5 detik dengan cleanup, dan checklist uji end-to-end (browser + curl).
12. Containerisasi & Rilis
   - Dockerfile multi-stage (satu resep tiga service lewat ARG), lapisan cache build, compose.yaml (healthcheck, depends_on service_healthy, volume, port rootless 8080:80), siklus operasional, dan checklist verifikasi lima lapis.
